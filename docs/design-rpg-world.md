# RPG 世界模块设计

> 目录约定：以下路径均相对 `src/`。
> `services/rpg/**` 除 `dialogue.ts` 外**一律纯 TS**：不 import vue / pinia；`time.ts`、`routine.ts`、`world.ts`、`noise.ts`、`names.ts` 另不 import three。
> 代码风格：无分号、单引号、2 空格，`noUncheckedIndexedAccess` 已开。

这份文档记录的是**决策与它们的失效模式**，不是代码复述。每一条「⚠️」都对应一次真实踩过的坑 —— 绝大多数是**静默失败**：不报错、不崩溃，只是画面或提示词悄悄变得不对。

---

## 0. 这个模块是什么

一个**程序化生成的可行走世界**，玩家走到 NPC 面前按交互键就进入沉浸式对话。它不是一个游戏，是**聊天的取景框**：世界存在的全部意义，是让每一轮对话都带上「此时、此地、对方正在做什么」。

| 层 | 文件 | 职责 | 依赖 |
|---|---|---|---|
| 噪声 | `services/rpg/noise.ts` | 环面 4D simplex，生态/高度/湿度/聚落/湖五个场 | simplex-noise |
| 世界查询 | `services/rpg/world.ts` | 「(x,y) 那格是什么」：可行走、高度、道具、村庄、地名、签名 | noise, hash, names |
| 地名 | `services/rpg/names.ts` | `(种子, 区域)` → 村名/野地名，纯函数不落库 | hash |
| 时间 | `services/rpg/time.ts` | 世界时钟、时段、天色关键帧 | palette, types |
| 作息 | `services/rpg/routine.ts` | 按周边地标推导 `{kind, pois, slots}` | world, time, hash |
| 几何 | `services/rpg/blocks.ts` | MeshBuilder + 烘焙顶点色明暗 | three/webgpu |
| 渲染 | `services/rpg/scene.ts` + `*.tsl.ts` | chunk 摆放、水面/泡沫/云影、昼夜调色 | three/webgpu |
| 主循环 | `services/rpg/engine.ts` | rAF、碰撞、NPC 仿真、时钟推进 | 以上全部 |
| 接聊天 | `services/rpg/dialogue.ts` | **唯一**允许 import pinia 的 rpg 文件 | stores/* |

存档很小：**地形是算出来的，不是存出来的**。`RpgWorld` 只存种子、生成参数、玩家位置、人设、NPC 与世界时刻。

## 1. 世界生成

### 1.1 为什么是环面而不是球

需求是「朝任意方向一直走都能绕回原点且看不出接缝」。**球面做不到** —— 正方格铺不满球面，必有极点奇异。环面（左右相接、上下相接）显示上仍是平面，四个方向各能绕一圈，既满足需求又不引入投影畸变。

接缝不靠贴图缝合，而是**让噪声本身在两个方向都严格周期**：把 `(x,y)` 映射到 4D 环面表面

```
P = (cos2πu·r1, sin2πu·r1, cos2πv·r2, sin2πv·r2)
```

再采 4D simplex。`u=0` 与 `u=1` 映射到**同一个 4D 点**，于是 `sample(0,y) ≡ sample(W,y)` 是数学恒等式 —— 不需要羽化、镜像或边界特判。

两个已堵上的失效模式：

- **偏移多圈掉精度**。同圈残差 ~1e-15（ulp 级，而生态阈值间距在 0.03 量级，差十几个数量级，翻不动任何一格）；但 `x+3W` 会被三角函数的幅角约减吃掉精度，实测 ~2.6e-5。所以对外查询**一律先 `wrapX/wrapY`**，这条路径上精度损失根本不会发生。
- **倍频写错**。每一倍频必须**整体缩放环面半径**，绝不能缩放 `u/v` —— 缩 u/v 会让高倍频周期不再是 1，接缝立刻回来，而且**只在世界边界处看得见**。

### 1.2 旋钮：只暴露生成器真能兑现的

`WorldParams` 里只有 `r1/r2/seaLevel/moistureBias/lakes` 被噪声层读；`districtGate/villageChance` 由 `world.ts` 消费。`r1`、`r2` 在存档侧被同一个 `gen.radius` 同时喂入，所以「环面长宽比」这个自由度**类型上存在、产品上没开**。

**贯穿一切的不变量**：每个生成参数的默认值都**等于参数化之前写死的那个常量**（`LEGACY_GEN`）。存档只存种子、地形每次现算，默认值一动，玩家回到自己的世界会发现海岸线和村子全挪了。于是「老世界地形不变」成了**类型签名的性质**（不传即老行为），而不是「记得回填」的纪律。`normalizeGen` 是第二道防线，不是第一道。

⚠️ `normalizeGen` 逐字段兜底而**不能用展开运算符**：`{...LEGACY_GEN, ...raw}` 会把半残存档里的 `undefined` 一并铺进去，把好好的默认值盖成空。

⚠️ `moistureBias` 必须加在 `sampler.moisture()` **内部**。湿度有三个消费方：生态判定、道具密度分档、`describeArea` 措辞。分散加偏置就会长出「按荒原密度长树的森林」。

⚠️ 四个场用**四个互不相关的种子**。高度与湿度相关 → 沙地只出现在固定海拔、像等高线；聚落场与湿度相关 → 村庄永远长在森林里；湖场与其它相关 → 湖成了高度场的副产品而不像湖。

**明确拒掉的旋钮**：地势起伏（会静默删掉村庄 —— `findVillageSpot` 要求 level 1..4）、季节、山脉走向。

### 1.3 内陆湖：两条刻意的决策

**不新增 `BIOME.lake`。** 加枚举要改七处 `b === water || b === shallow`（可行走、挡路、高度、水面网格、泡沫、措辞……），每处都是一次「忘了改」的机会，漏一处就是「湖能走上去」或「湖没有泡沫」。不加枚举则 `scene` / `water.tsl` / `walkableAt` / `BLOCKERS` **零改动**，湖天生有波纹、岸线泡沫和可蹚的浅边。代价是「是不是湖」需要单独一问 `isLakeAt`，但它只服务地貌措辞，渲染层不需要区分。

**⚠️ 高度带 + 八邻检查这道门是全部关键，不是优化。** 设计时以为「高度带下界在浅滩带之上 → 内陆是结构保证」，**实测推翻**：带宽只有 0.02，坡陡处不足一格宽，1383 个湖格里有 **201 个贴着海**。补上「八邻只要有一格低于浅滩线就不算湖」之后，4237 个湖格**零个**贴海。判据必须用**原始高度**而不是 `biomeAt`，否则递归回 `lakeKind`。

⚠️ `biomeAt` 与 `levelAt` 是**两个各自读同一高度场的函数**，湖判定必须同时加进去。只改前者的后果：湖床按陆地台阶渲染，而水面钉死在常量高度 —— 水面跑到地形**下面**，湖里外翻转。**单看任一函数都发现不了。**

⚠️ `lakes` 缺省必须是 `false`（`g.lakes === true` 而非 `?? true`）：兜底成 true 会让所有老存档一夜之间长出湖来。

### 1.4 河流：拒掉

四条独立理由，任一条都足够：噪声脊不会往低处走；要它往低处走就得预计算全局高度图 + 排序，直接违反本模块「零存储、逐格纯函数」的架构；环面**没有出水口**，全局流场根本不存在；渲染层假设水面只有一个高度，河流逐台阶下降会在每一级引入接缝。想要「流水的样子」就用现成的 `pathAt` 机制做一条装饰性的溪。

### 1.5 村庄与地名

村庄按 24 格区域惰性求值并缓存：聚落场门控分出文明大区 → 掷骰子 → `findVillageSpot` 螺旋外扩找 1..4 级草地。房屋用 3×3 哈希严格极大值法保间距，两房必然不相邻。村道是过村心的十字加哈希留缺口，像被人踩出来的。

⚠️ `hashTile` 用 murmur3 的 fmix32 而不是 `fnv1a("seed:x:y")`：FNV-1a 对只差末位的短字符串雪崩很差、高位几乎不变，而调用方恰好取高位 —— 结果是同一列上连续七八格同时低于阈值，**树排成竖柱**。

地名是纯函数、不落库 —— 落库就成了第二个真相源，迟早与地形对不上。中间那个字按**当地地貌**选表（湖边叫「塘/湾」、林里叫「松/林」），名字才像是长在那儿的；这两次采样在定村心时本来就算过，等于白捡。

⚠️ 野地后缀也必须**按地貌分表**，否则会生成「枫原林」这种中间说平地、结尾说树林的自相矛盾名字。
⚠️ 特征字表与后缀表在 林/樾/木、岭/岗、原 几处重叠，撞上会生成「枫原原」「梅林林」叠字 —— 靠顺延一位而不是手工去重两张表。

**⚠️ 判断「在不在村里」只能用 `world.villageAt()`，绝不能嗅 `describeArea` 的字面量。** `VILLAGE_SUFFIX` 有 **村/庄/屯/寨/坞/铺/集 七种**，`includes('村')` 只认得出一种 —— 作息模块就是这么把 18 个村子里 17 个的村民判成「游荡者」的，而游荡者没有社交时段，整个村子白天各走各的、傍晚也不串门。

### 1.6 兼容性预言机

⚠️ `signatureAt` 必须把**台阶等级**与**道具的 variant/rot/ox/oy** 都摘进去。旧版只摘 `biome:path:propKind`，于是「只改高度不改生态」的格（海平面、内陆湖正属于这一类）在旧签名下看起来「一样」—— 拿它证明兼容性**等于没证**。以后再加地形维度必须同步扩这里，否则断言会退化成橡皮图章。

## 2. 渲染

### 2.1 三层坐标系

| 帧 | 范围 | 谁拥有 | 用途 |
|---|---|---|---|
| 逻辑 | `[0,W)×[0,H)` | engine | 存档、碰撞、NPC、`nearestNpc` |
| 渲染 | 逻辑 ± W | scene | 每块 chunk 取离玩家最近的那个环面镜像 |
| 噪声 | 渲染 + `noiseOrigin` | scene | 连续、永不瞬移；只喂 TSL 噪声 |

玩家从 255.99 走到 0.004 时，逻辑上只挪了 0.014 格，**整幅画面的渲染坐标却同时减了 256**。几何上这一步看不出来（相机、地块、角色同步平移，逐像素相同），但水面/泡沫/云影的噪声按渲染坐标取样 —— 不补偿就会在跨缝那一帧**整屏重掷**，过接缝时「闪一下」，而那条子午线正是绕行一周的必经之路。

`noiseOrigin` 只在跨缝那一帧变化 ±W，正好抵消整幅平移；平时恒定不变，一分钱不花。

**被否掉的两个替代方案：**

- 「渲染帧改成不回绕的里程表」—— 概念更少，但 three 默认的 `modelViewMatrix` 是**在着色器里用 f32 乘**的，坐标一大就灾难性抵消，抖动约 `|锚点| × 2.6e-6` 像素，约 150 圈后肉眼可见。三层坐标把顶点永远锁在 ±300，**精度相对今天零退化**。
- 「按逻辑坐标取噪声」—— 花纹锁在地形上（听着更对），但会在渲染接缝处留一条**永久硬线**，比每圈闪一次严格更糟。

### 2.2 最近环面镜像与「恰好覆盖一次」

`dx = wrapDelta(P - c.cx, W)`，`ox = (P - c.cx) - dx`。由 `wrapDelta` 的定义，`ox` **只能是 0 / +W / -W** —— 地块永远落在自己的真镜像上，不会出现分数偏移；而渲染后中心到玩家的距离 `|dx| ≤ W/2` 是所有镜像里的最小值。

「恰好一次」是**结构性的**而非运气：`ox` 是单值函数（`d = ±W/2` 的平局被确定性地判给 `ox=0`），每个 chunk 只有一组网格、每帧只被赋一次位置 —— 想画出两个镜像在物理上都做不到。

真正的风险是反向的**漏**：一旦 `viewR > (W−CHUNK)/2 = 112`，取景框比基本域还宽，本该在两侧同时出现的 chunk 只会出现一边。所以 `resize()` 里把它写成 **clamp 而不是注释**。要撞上这个上限需要约 5540×5540 CSS 像素的视口（1080p 下需要的是 55，4K 是 87）—— **5K 以内都用不着退路**。

⚠️ `viewR` 曾写死 52，**本来就不够**：1080p 需 ≈55、4K 需 ≈87（纵向被俯角拉长 `1/sin(32.4°)≈1.87` 倍）。也就是说普通桌面上角落的 chunk 一直在闪。现在由视口推导并 clamp。

四层网格（地/影/水/泡沫）按 chunk 分组而不是平铺，于是「同一块的四层必须去同一个镜像」成了结构保证，且每帧从 256 次算成 64 次。`placeRig` 用同一条规则，屏幕距离恒等于 `nearestNpc` 算的环面距离。

### 2.3 TSL：`modelPosition` 与 `positionWorld`

水面几何是**建构时的绝对坐标**，而地块会被挪走。于是接缝两侧共享边的水面，一片 `positionLocal.x` 是 256、另一片是 0 —— 按 `positionLocal` 算波高则 `waveY(256) ≠ waveY(0)`，**水面沿接缝开裂**，最大 ±0.26 世界单位（≈ 屏幕 4.7px）。

⚠️ 顶点阶段又**不能**改用 `positionWorld`：`NodeMaterial.setupPosition` 里是 `positionLocal.assign(positionNode)`，而 `positionWorld` 由 `positionLocal` 推出 —— 引用它就是自引用。正解是 `modelPosition`：每对象一个取自 `matrixWorld` 平移的 vec3 uniform；地块只平移不旋转不缩放，它正好就是那次挪动量。

片元阶段的 `positionWorld` 本来就是对的（已吃到平移），只需再补 `noiseOrigin`。

⚠️ **水面与泡沫必须用同一个坐标表达式**，否则泡沫不再骑在浪上。

### 2.4 `matrixAutoUpdate` 陷阱

chunk 位置一年也变不了几次，所以 `matrixAutoUpdate = false`。代价：改了 `position` 必须自己 `updateMatrix()`。

⚠️ 漏掉**不会报错** —— `Scene.matrixAutoUpdate` 仍为 true，每帧从那个**陈旧的 `matrix`** 重算 `matrixWorld`，物体静默画在老地方，连视锥剔除都拿旧包围球去测。症状是「chunk 莫名其妙闪进闪出」。

`debugSnapshot()` 刻意从 `matrixWorld.elements[12]/[14]` 读而**不从 `position` 读**，就是为了让这个静默失败被同一条断言抓住 —— 从 `position` 读的快照会照样「正确」。

### 2.5 烘焙顶点色明暗

相机固定正交、太阳方向恒定，逐帧算光照纯属浪费：建几何时就把 `AMB + (1−AMB)·max(0, n·L)` 乘进顶点色，全程 unlit。

⚠️ `topQuad` 刻意**不走叉积、硬编码法线 +Y** —— 同高度的格子明暗必须**逐位相同**，否则浮点差在拼接处闪成补丁。
⚠️ `sideQuad` 的法线由上棱方向绕 Y 转 −90° 得出，所以 `sides` 表里四组端点的**书写次序是载荷而非风格**：写反了立面明暗就反了。

这一设计直接换来昼夜调色的代价为零（见 2.6）。

### 2.6 昼夜：`dayTint` 与 `sunAmount`

basic 材质的片元就是 `diffuse × vColor`，一行 `setRGB` 就给整张地图调色，**零几何改动、零重建**，WebGPU/WebGL 语义一致，分量可 >1 所以正午还能提亮。雾（正交下会把地图切成一条带）、全屏覆盖面、自写 NodeMaterial 都被否掉。

**硬约束：上午 08:00 的乘子恒为纯白** —— 白天与做这个特性之前**像素级一致**，整个特性等于「现在这套是白天的样子」，回归风险为零。（已用截图比对验证：~99–100% 匹配。）

⚠️ **水面与泡沫是 TSL 图，`colorNode` 完全绕开 diffuse，`material.color` 对它无效。** 不额外接一个 uniform 的话，入夜后整片湖**惨白发亮**，成为画面里最刺眼的东西，昼夜这件事当场穿帮。—— 这是靠 22:30 的截图发现的，纯逻辑断言全部通过。三者（terrain / figure / dayTint）必须写同一个值，否则「地暗了湖还亮着」。

⚠️ tint 必须乘在 **glint 之后**；只压暗基色会让夜里水面剩下一层亮白碎点。

⚠️ **云影必须按 `sunAmount` 淡出。** 云影是**日光**被挡出的暗斑；夜里没有日光却仍压暗 40%，看上去是一团团无缘无故的黑雾在夜色里爬。贴地投影 `shadowMat.opacity` 走同一个 `s.sun`，两者必须一起淡出。

⚠️ **色空间：`SKY_KEYS` 的 hex 按肉眼颜色（sRGB）写，而 `Color.setRGB` 在 three 默认工作色空间下是直接当线性值写进去的。** 漏掉 sRGB→线性转换，线性 0.47 显示出来约 0.72 ——「深夜」看上去只是个阴天的下午。同样是截图发现的；纯白转换前后仍是 1.0，所以上面那条硬约束不受影响。

⚠️ **`sky` 与 `tint` 都要转** —— 这里有一个很像样的错误推理，我自己完整走过一遍并差点提交：`sky` 进的是 `scene.background`，而 `renderers/common/Background.js` 确实用**工作色空间**（线性）把它读进 render pass 的 `clearValue`，画布格式又是非 sRGB 的 `bgra8unorm`，看上去「清屏色没有输出编码，所以不该转」。这个推理**少看了一层**：`Renderer.needsFrameBufferTarget` 在 `outputColorSpace(sRGB) !== workingColorSpace(线性)` 时恒为 true，于是整帧先渲进一个**线性的中间 RenderTarget**（清屏色也在里面），再由 `_renderOutput` 用一张全屏 quad 做线性→sRGB —— 背景和地形一样被编码。跟进 `clearValue` 看到的是那个中间 target 的清屏，不是画布的。three 自己的注释写着「Unlike in `WebGLRenderer`, this is done in a separate render pass」。

旁证：做昼夜之前这里本来就是 `new THREE.Color(0xece9df)`，而 `setHex` 默认按 sRGB 解释并转成线性 —— **转换后的值才是原本的基线**，不转反而会让白天偏离。教训是：追渲染管线的色空间时，`clearValue` / `format` 这一层还不是终点，要一直追到「谁最后写进画布」。

三个 uniform 集中在 `frame.tsl.ts`，因为水/泡沫/云影**必须在同一帧同步补偿** —— 补了的那层和没补的那层在同一帧里对不上，比不补还刺眼。

## 3. 引擎：时钟、作息与移动

### 3.1 时钟按 dt 累加，不反推墙钟

`clockTotal` 只在 tick 里被 `dt × timeScale` 推进，而 dt 先被 `MAX_DT = 0.05` 夹住。

不用墙钟是因为 NPC 的位置是**玩家离开那一刻的快照**：隔三天回来，墙钟会把时间推到一个随机时辰，而全村人还站在三天前的格子上 —— 一进门就是集体瞬移。**世界在你不看的时候就该是停着的。** 夹 dt 还顺手解决了第二件事：碰撞是按步进采样的，切回标签页那一帧若真的走了几秒的距离，角色会直接跨过水面到对岸。

⚠️ 「上一分钟」`lastMinute` 必须**跨帧持有**，不能在帧首现读 `clockTotal` 反算。`addClockMinutes` 是在两帧**之间**改值的，现读会把那 5 分钟算进 `prevMinute`，`minuteChanged` 恒为 false，换段和天色都收不到跳变 —— `timeScale=0` 的世界里这是永久性的。

⚠️ `scene.setTimeOfDay` 必须在**第一帧之前**调用一次。只在 `minuteChanged` 时刷新的话，存档记着 23:00 进游戏会先亮一下白天再暗下去；冻结世界更是永远停在白天。

### 3.2 对话期间冻结，每轮定额 +5

模型花的是现实时间，故事里你们只是交换了几句话 —— 照现实走一次对话等于游戏里五小时，刚写进提示词的时段当场作废，聊完对方「应该」早就不在原地。

⚠️ 世界时刻**必须有一道独立的落盘兜底**（每 30 游戏分钟）。只搭「跨格 / 关对话 / 离开页面」的顺风车是不够的：站着不动看风景半小时再关掉标签页，`onBeforeUnmount` 在硬刷新/关页时并不保证跑得到，下次进来世界时间就**倒流**回上一次存档。

### 3.3 作息是会移动的锚点，不是新状态机

按周边地标确定性推导 `{kind, pois[3], slots}`，**推导一次随存档落盘** —— 与 `homeX/homeY` 同一套路：此后算法再怎么调，老 NPC 的家也不会悄悄搬走。

运行时刻意**不新增状态机**：`enterSlot` 只是把当前时段的 POI 写成锚点 `hx/hy`，「在这点附近走走停停」白捡了原有的 idle↔walk。真正需要新增的只有换段那一刻的长距离位移（`travel` 相）—— 而那恰恰是硬拴绳会把人瞬移拽回去的地方。

⚠️ 段边界必须带 ±40 分钟哈希抖动，否则全村**同一秒集体转身**，比不动还出戏。
⚠️ 社交 POI 要跳过已被「干活」占用的那一格，否则 NPC 一整天只在一个点上换措辞，作息看上去等于没有。
⚠️ 换段条件必须是 `minuteChanged || rt.slot < 0`。后半条是给 `timeScale=0`（文档写明「冻结」）的世界兜底，否则 NPC 一辈子拿不到 POI，提示词里人人「站在原地歇脚」。
⚠️ `enterSlot` 的早退只允许在「段号、hx、hy 三者全相同」时发生。只把 `hx/hy` 换掉就 return 的话，下一帧拴绳会按新锚点做一次**货真价实的瞬移**。

### 3.4 travel 与挂起的拴绳

硬拴绳把人夹在锚点半径内。若通勤时仍生效，第一帧就会把 NPC 拽回去，**永远到不了田里** —— 所以 travel 分支下不跑拴绳。

⚠️ 玩家走近时冻住运动但**不动 `rt.phase`**。原先无条件置成 idle，加上 travel 之后就意味着：玩家从一个正在赶路的 NPC 身边走过，它会**永久忘记自己在赶路**。

### 3.5 四级卡死阶梯与诚实的放弃

没有寻路。每 0.75 秒量一次到目标的环面距离，进展 < 0.05 记一次 stuck：

1. stuck=1 → 插一个法向 2.5 格的绕行点，左右由 id 哈希定（全村不会同时朝一边闪）
2. 到绕行点 → 续原目标并清零
3. 同村长距离 → 先上村道十字臂（`pathAt` 现成判据、村道恒无道具）
4. stuck≥4 → 把锚点改成当前位置转 idle，并置 `stranded = true`

**全程绝不瞬移。**

⚠️ `stranded` 唯一的作用是措辞，但它是必须的：不记这个标志，`npcStateText` 会走回「正在照看庄稼」那一支 —— 人站在谷仓边，提示词却说它在田里干活，**等于拿假情境喂模型**。放弃可以，撒谎不行。诚实版本读作「在谷仓边，本想去田里照看庄稼，一时没能过去」—— 而且更有戏。

实测：约 **8.3%** 的 POI 是真走不到的（田在湖对岸之类）。这是「无寻路 + 噪声地形」的固有代价，设计时已接受。

### 3.6 轴分离碰撞与 standCache

玩家与 NPC 都是两轴分开试探，于是贴墙斜走会**滑行**而不是整个停住。

⚠️ 差别在失败处理：漫游撞墙就放弃该分量（`rt.tx = rt.x`），**通勤时不能放弃** —— 那等于取消通勤，要保留目标让另一个轴带着滑过去。

⚠️ `canStand` 必须按整数格记忆化。世界确定且静态，所以这份缓存是**精确**的、不是近似。不缓存则每次要重算三个 fBm，20 个 NPC @60fps 约**每秒七万次噪声取样**；作息让 NPC 走得更多，所以这是必要而非镀金。

### 3.7 必须走 `wrapDelta` 的每一处

前提是坐标已回绕进 `[0,m)`，所以「`rt.x/rt.y` 每帧回绕」「落盘前先取模再 floor」（直接 floor 会把 −1 存进档）是这一切的地基。

必须过 `wrapDelta` 的六处：**距离**、**朝向**、**移动位移**、**到达判定**、**绕行法向**、**拴绳夹回**。渲染侧同样：`placeRig` 的最近镜像、`setPlayer` 的噪声原点补偿与 chunk 重摆。

⚠️ 漏掉任何一处的症状都一样：接缝对面 12 步远的田被算成 251 格，NPC 朝**反方向**绕世界走，而卡死阶梯量的是环面距离，看它「越走越远」，3 秒后就地放弃 —— 表现为「农夫永远到不了自家田里」。
⚠️ 朝向漏掉的版本：接缝对面一格的 NPC 转身朝一个隔着大半个世界的你。
⚠️ 拴绳漏掉的版本：把人拽过大半个世界。作息把这条从「几乎撞不上」变成「随时可能」—— POI 按地标找，完全可能落在锚点的接缝对面。

### 3.8 NPC 上限

`NPC_MAX = 20`。按渲染与仿真成本定：每个 NPC 的 rig 实测是 **10 个 mesh**（不是注释一度说的 6），20 个就是 200 个 draw call，已与整张地形的可见 chunk 数同一量级。

⚠️ **上限只挡新建，绝不在读档时截断。** 三条理由：
1. `normalize()` 不回写，真截断了也要等某次**无关的** save 才落盘 —— 而游戏页每跨一格就 save 一次，用户会在打开世界几十秒后莫名其妙少掉几个从没动过的 NPC；
2. 每个 NPC 都挂着 `chatId`，砍掉它就**孤儿化一整段对话历史**，且不留任何线索说明那段对话属于谁；
3. 上限本来就不是不变量 —— 导入备份（`services/io/backup.ts`）与设备同步（`services/sync/session.ts`）都是**零校验原样回写**的。超编世界确实存在，编辑器里给一条非破坏性提示即可。

### 3.9 作息面板（`NpcEditor`）

面板显示推导出来的 `kind` / POI / 一天的行程，允许改 POI 的**地点名、在做什么、活动半径**，并提供「按当前位置重新推导」。

⚠️ **重新推导必须由引擎做，不能让 UI 自己算完塞进 `npc.routine`。** 运行时记着 `rt.slot`，而 `enterSlot` 在段号没变时会早退 —— 换了新 routine 却不清 slot 的话，改动要等到下一个时段才看得出效果，在用户眼里就是**点了没反应**。`engine.rederiveRoutine()` 负责把 slot 归零。

⚠️ **`enterSlot` 判断「POI 变没变」只能用 `rt.poiX/poiY`，不能用 `rt.hx/hy`。** 后者是**共用槽位**：卡死阶梯放弃时会把它改写成「就地漫游的锚点」（当前浮点坐标）。用 `hx/hy` 判身份的话，放弃之后 `poi.x + 0.5 !== rt.hx` 恒成立，下一个游戏分钟就会被当成「POI 变了」重新进段 —— `stranded` 被清、重新 travel。「体面放弃」变成「放弃一秒后无限重试」，而那句诚实的「本想去…一时没能过去」成了**死代码**。（实测修复后：1.85 游戏日内 `stranded` 保持 86.4%。）

⚠️ **半径收窄必须走 travel，不能只改 `rt.roam` 就返回。** 硬拴绳是**一帧到位的夹取**（`k = (roam+0.5)/dd`），不是逐帧收敛 —— 把 12 改成 1，下一帧人就被瞬移十来格。

⚠️ **半径要在引擎侧自己校验，`?? 2` 兜不住。** `v-model.number` 在输入框被清空的那一刻写的是**空串**，而 `'' ?? 2` 还是 `''`；拿去比大小会当 0 用（`'' + 0.5` 是字符串 `"0.5"`）。面板这边也改成失焦时才写一个校验过的数字，模型里永远是 number。

⚠️ **`<details>` 的内容要自己包一层 div。** 现代 Chrome 把非 `summary` 子节点整个塞进 `::details-content` 匿名块盒（实测 Chrome 152：`display:block`），`display:flex; gap` 只作用在 `[summary, ::details-content]` 之间 —— 各行实测间距是 **0**，末尾的说明还会反向压到按钮上。

⚠️ **警示文字不要用 `--cbx-warning` 当前景色。** `#fab005` 12px 压在白底上实测对比度 **1.86:1**（WCAG AA 小字要 4.5）。琥珀色做底色与左边条、字用正文色，实测 7.67:1。

## 4. NPC 对话如何接进聊天管线

### 4.1 一行提示词逻辑都不写

`dialogue.ts` 只做三件事：把 NPC 身份写进会话的 `chat_metadata.rpg`、把 `chats.current` 切到这段会话、追加玩家那句话，然后调 `gen.send()`。世界书、深度注入、状态卡、流式、落库全部复用既有管线。

### 4.2 为什么身份记在会话上，而不是靠参数传

NPC 会话就是一段普通的 `kind:'solo'` 会话，侧栏里点得进去。玩家完全可能走出游戏、在聊天页接着跟这个 NPC 聊，或者点 ↻ 重新生成 —— **这两条路都不经过 `dialogue.ts`**。

最硬的证据是 `regenerate()`：它 `await chats.removeTail(1)` 后直接 `send()`，签名里连传参的位置都没有。所以任何「调用方传 override」的方案在 ↻ 这条路上是**结构性不可达**的，不是忘了传。

后果不是报错而是**静默漂移**：前半截对着「旅人阿柚」说，后半截突然变成全局人设；全局人设 description 为空时整个【用户设定】段直接消失；无卡 NPC 更会退回「一个乐于助人的 AI 助手」。

⚠️ `rpgBinding` 必须保持**同步**且**自包含**：`build()` 拿不到 `await`，所以绑定里不能去查世界存档 —— 这是它要冗余存 `worldName`/`npcName`/`persona` 的原因。

绑定**每轮重写**而非建会话时写一次：世界简介、玩家身份、关联卡都能在 `NpcEditor` 里随时改，而 chatId 不作废。

### 4.3 无卡 NPC

⚠️ 纯游戏 NPC 没有 `characterId`，`chars.byId(undefined)` 查不到，`resolveSpeaker` 会**静默**落到 `defaultAssistantCharacter()` —— 用户写的 NPC 简介一个字都进不了提示词。`synthNpcCard` 合成一张只在一轮生成里存在、不落库、不进角色列表的临时卡。

它放在 `types/` 而不是 rpg 服务层，是因为 `build()` 要用它，而它不能 import `dialogue.ts` —— 那个文件反向 import 了 generation store，会绕成循环依赖。

`nativeIdentity` 是最后一层兜底：简介为空时给「『世界名』的原住民」。兜底而非留空，是因为空简介让模型无所依凭、张口就飘到现代都市；「本地人」配上作为【场景】进提示词的世界简介，足以让对话落在这个世界里 —— 玩家在地图上随手放个 NPC 就能直接说话。

### 4.4 situation 与 15 分钟 TTL

`situation` 由 `npcStateText` 实时生成：「此刻是黄昏 18:20，对方在谷仓边，正要去田里照看庄稼」。它与 `worldDescription` 拼成 `scenarioPrefix`，**追加**在角色卡自带 scenario 之前而不是替换它 —— 世界简介说「这是个什么地方」，卡的 scenario 说「你们怎么碰上的」。

⚠️ `npcStateText` **不得自带【】标签** —— 外层 builder 会把整块包进【场景】，自带一个就成了标签套标签。

**失效机制要说准**（这一条我先前判断错过一次）：`patchMetadata` 是顶层浅合并、补丁整体替换 `rpg` 对象，所以省略键确实能清掉 —— **真正漏的是聊天页续聊 / ↻ 根本不经过 `dialogue.ts`**，它们直接读那份持久值而无人重写。于是不加保质期的话，模型会在半天之后仍被告知「对方此刻在村道上」，而那个人早就回家睡下了。**宁可不带，不可带错。**

15 分钟的取值逻辑：游戏里每轮都重写，所以在游戏里永远不会过期；只有「关掉游戏、隔了一会儿从聊天页接着聊」才撞线，而那正是它该失效的场景。太短则玩家刚退出游戏点 ↻ 就丢情境，太长等于没加。

⚠️ `situation` 与 `situationAt` **同生同死**。只写一个的话，要么老时间戳给新 situation 背书（提前过期），要么新时间戳给老 situation 续命（永不过期）。没有时间戳的旧数据一律当过期。

### 4.5 `ensureChat` 里的播种顺序约束

⚠️ `createSolo` 必须在**建会话那一刻**就收到 `world.persona`。开场白里的 `{{user}}` 在播种时被展开并**永久落库**，而且 `pickGreeting` 展开的是**整个 swipes 池**，左右切换只做数组取值、不重新求值 —— 此处用错身份，池里每一条都错且永久错。

这也解释了 `seedGreeting` 为什么不能自己去读 `meta.chat_metadata.rpg`：RPG 这条路是先 `createSolo`（此刻开场白已渲染落库）、**之后**才 `patchMetadata` 写绑定，读到的永远是 `undefined`。

所以顺序是硬的：**persona 靠参数传进建会话、绑定靠 metadata 供之后每一轮** —— 这是整条链路里唯一一处必须传参、且 metadata 方案不可行的地方，恰好与其余部分相反。

## 5. 如何验证这个模块

这个模块**没有测试运行器**（`package.json` 里只有 `type-check` / `check-templates`）。验证靠的是代码里已经埋好的只读钩子 + 一条能停下来的 rAF。

### 5.1 现成的钩子，各自为了抓什么

| 钩子 | 位置 | 为了抓什么 |
|---|---|---|
| `World.signatureAt` | `world.ts` | 绕圈闭环；「改动前后地形逐格一致」的兼容性预言机 |
| `SceneHandle.debugSnapshot()` | `scene.ts` | chunk 覆盖/重影/空洞；**从 `matrixWorld` 读**以抓 `updateMatrix` 遗漏 |
| `globalThis.__rpg`（仅 DEV） | `RpgPlayView.vue` | 整个 `EngineHandle`，可在控制台无竞态驱动 |
| `?webgl=1` | `RpgPlayView.vue` | 移动端唯一会走的回退路径，此前**根本没法验** |
| `world.villageAt()` | `world.ts` | 「在不在村里」的唯一合法判据 |

### 5.2 在控制台无竞态地驱动引擎

先 `__rpg.stop()` 取消 rAF，再自己调 `scene.setPlayer()` / `scene.render()`。不停的话 `tick` 每帧都会重写 `setPlayer` 并 render，断言的快照是被下一帧覆盖过的。

```js
const e = globalThis.__rpg; e.stop()
const s = e.scene, W = 256, snaps = []
for (let i = 0; i <= W * 4; i++) { s.setPlayer(x0 + i * 0.25, y0); snaps.push(s.debugSnapshot()) }
e.start()   // 验完必须还回去
```

`setPlayer` 自己回绕入参（传 256 与传 0 完全等价），所以可以直接喂单调递增的坐标绕满一圈。要驱动移动就 `e.input.setStick(1, 0)`，别去合成键盘事件。

### 5.3 零 token 验证

- **纯 service 直接动态 import**：`world.ts` / `noise.ts` / `names.ts` / `routine.ts` / `time.ts` 都不 import vue/pinia，three 只在 `scene.ts` 里动态 import。所以在 dev server 的**任意页面**控制台里 `await import('/src/services/rpg/world.ts')`，就能在没有渲染器、没有世界页面、没有模型的前提下验地形、村庄、POI、签名、天色。`findStandSpot` 被特意从 engine 搬到 world 就是为了这个。
- **对话链路 stub `globalThis.fetch`**：provider 直接用全局 fetch，临时换掉它喂假 SSE，就能验 `talkToNpc` 的落库、中断、以及情境串拼进【场景】，一个 token 不花。⚠️ 手造的 `Response` 不会自己取消 body，要显式接 `signal.addEventListener('abort', …)`。验完记得还原。

### 5.4 值得断言的不变量

| # | 断言 | 抓的是 |
|---|---|---|
| 1 | 绕行一周，背景色像素数**恒为 0** | 世界有边（正交俯视下每个像素都该打到地面） |
| 2 | 跨子午线逐帧像素差无孤立离群值 | 噪声重掷 / 水面开裂 |
| 3 | `debugSnapshot().chunks` 每个 `ox%W===0`、恰好覆盖一次 | 分数偏移、重影、空洞 |
| 4 | 任意分辨率下 `viewR ≤ (W−CHUNK)/2` | 同一 chunk 两个镜像同时入画 |
| 5 | 游玩期 `geometries` **逐位不变** | 「零重建」这个卖点 |
| 6 | 逐帧 NPC 位移 ≤ `NPC_TRAVEL_SPEED × MAX_DT` | 任何形式的瞬移 |
| 7 | 所有 POI 都 `walkableAt && !blockedAt` | NPC 永远走不到的目标 |
| 8 | `autoRoutine` 同输入两次调用逐位相同 | 确定性 |
| 9 | `skyAt(480).tint` 恒为纯白；1440 === 0 | 白天回归基线；午夜跳变 |
| 10 | `npcStateText` 不含 `【` | 标签套标签 |

⚠️ **T2 类断言必须在修复之前先跑一遍，它应该响亮地失败** —— 那才说明这条测试有牙。

⚠️ **纯逻辑断言不能替代看一眼。** 本期两个最严重的视觉缺陷（水面不随昼夜变暗、色空间漏转换导致夜晚过亮）**逻辑断言全部通过**，是靠 22:30 的截图发现的。凡是改了「看起来什么样」的东西，截图是必需的一步。

### 5.5 长期房规（每次验证都适用）

- **先备份数据库**再跑浏览器自动化 —— 曾在真实数据上跑自动化丢掉用户对话记录且事后查不出原因。收尾逐 store 与备份核对计数。
- **只在自造的临时对象上**验删除/破坏性操作（临时世界、临时 NPC）；按文本点按钮要限定容器。
- **视口模拟必须撤销**：`emulate` 作用在用户的**真实标签页**上，留着不撤会让用户看到「右侧空白 + 内容截断」。收尾清除并用 `innerWidth === outerWidth` 断言证明已还原。
- **不花用户的 token**：LLM 真调用需要显式授权，默认一律走 stub。

---

## 6. 为什么不 bump `DB_VERSION`

本模块历次改动都**没有**结构变更、没有新索引，读路径回填（`normalize`）是本仓既定机制。而 `db/schema.ts` 里记着一次真实事故：版本号与建表分在两次提交，中途刷新过的库**永久报废**、连 API 密钥一起赔进去。没有结构需求时 bump 纯是下行风险。
