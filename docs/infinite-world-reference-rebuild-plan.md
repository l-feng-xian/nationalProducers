# 无限世界：按 town-reference 重构的实施方案

日期：2026-09-17。状态：**用户已以“开始执行”批准。本轮素材生成、torus-4 布局和 v6 渲染重构已接入；实现及复核记录见 [v6 交付记录](infinite-world-visual-v6.md)。以下分析保留为实施前的基线，不代表最终效果。**

唯一视觉基准：`output/imagegen/world-v5/raw/town-reference.png`，1536×1024。此前 v2 原图只作为历史资料，本轮不再用它替代这张参考图。玩家保持已确认的黑发、红黑服饰和当前显示大小。

## 1. 目标、边界与实现路线

目标是让游戏中能行走、能遮挡、能交互的地图，在构图、材质笔触、物件比例、边界结构和环境细节上遵循这张图。现有 v5 的形状和密度差距很大，需要同时重做素材、空间布局与渲染层。

先使用正式渲染器制作一个固定的“参考城镇”基准场景：左侧弯河及木桥、中央方形水井广场、北侧商店和旅店、两侧及南侧住宅、东北谷仓和菜地。这个场景是后续程序化规则的标尺，不能靠整幅参考图铺在屏幕上代替可玩的场景。基准场景通过逐区域视觉验收后，再推广到种子驱动的世界。

“百分百还原”需要区分：单张图的每个像素可以通过直接显示原图保留，但无法同时保证独立物件、任意程序化布局、角色遮挡和动态水面仍逐像素相同；生成模型也不能保证补画后的隐藏区域等于原作者原意。本方案不虚报 100% 相似度，不将自动化测试通过等同于美术达标。以参考场景的逐项复现、局部对照和用户视觉验收判断效果，明确记录剩余差异。

## 4. 技术重构范围

保留 Vue、Three.js TSL、WebGPU/WebGL 后端及现有玩家动画。重点修改生成到绘制的数据结构，而非更换引擎。

1. **参考城镇与比例标尺**：增加固定场景定义，记录参考图中的广场角点、水井、各门口、桥头与农田范围。固定 1536×1024、DPR=1、晴天、相同时间与相机。用水井、门宽、桥宽逐一对齐物件比例；保持当前玩家显示大小，调整街区和院落间距，不整体放大所有建筑。绘画中的投影不完全等同于真实相机，先用现有正交视角标定，再决定是否调整俯角；不能从一张图断言精确镜头参数。
2. **连续视觉边界**：为岸线、道路、石板区域、庭院、田床保留连续曲线/多边形及语义。逻辑网格继续提供导航，但美术边缘、作物行距、小石块位置不受整格限制。岸边和道路细节由同一边界数据派生，避免多个层各自抖动导致接缝。
3. **分层地面与对象**：河床→水面→岸石/岸草；路面→路肩/缝草；石板内部→收边石；土壤→垄肩/暗沟→作物根影→作物。大房屋、桥栏杆、树冠按遮挡需求分层，不将所有细节塞进一张平面大图。
4. **图集分档**：角色动画和小物保留 256² 档；建筑、大树等使用独立的 512²/必要时 1024² 档，按实际屏幕大小和 DPR 选择。源素材保留更高分辨率。当前 162 层的 256² RGBA 图集基础数据约 40.5 MiB，不含 mip；全部提升到 1024² 会涨到约 648 MiB，因此必须分组而非全局提高常量。
5. **素材元数据**：除 file/pivot 外补充真实门口锚点、占地多边形、庭院连接点、阴影轮廓、允许方向、贴图分档和遮挡层。采样使用透明边缘颜色扩展；固定光照素材避免任意镜像或旋转造成受光方向翻转。
6. **水流和阴影**：将已有水文流向/中心线转为可采样流场；水面沿局部方向流动。建筑、树群和桥使用对应轮廓的定向短投影与接触暗部；防止与素材自带阴影重复叠黑。全场以参考中的受光关系为准，不推导不存在的光照精确数值。
7. **布局与碰撞**：模板表达广场、公共建筑、住宅院落、河桥和农场的关系与合法变形范围；地形不容纳时调整/换模板，不能删到只剩随机散点。狭窄院门、桥栏杆和田间道检查角色碰撞宽度；必要时仅细化城镇局部碰撞/寻路，避免视觉能走而逻辑被整格挡住。
8. **版本兼容**：冻结当前 `torus-3` 基线，再以 `torus-4` 承载新布局。新素材走 `public/world/v6`；旧存档按版本使用相容的建筑轮廓和门口锚点，不将新占地直接套到旧设施上。新城镇重构以新世界或专门基准场景验收。

主要代码落点：`generation/hydrology.ts`、`generation/pipeline.ts`、`generation/villageLayout.ts`、`generation/roads.ts`、`rendering/contourField.ts`、`groundField.ts`、`ground.tsl.ts`、`water.tsl.ts`、`spriteAtlas.ts`、`sprite.tsl.ts`、`decorBuild.ts`、`plotBuild.ts`、`plot.tsl.ts`、`farmCrops.ts`、`chunkBuild.ts`、`chunkMesh.ts`、`camera.ts`。新增的边界与模板逻辑应独立成纯函数模块，保持可测试。

## 5. 素材生成安排

使用 **`gpt-image-2.5-flare`** 和已配置的 `OPENAI_API_KEY`、`OPENAI_BASE_URL`，通过 imagegen 技能的官方 CLI/API 路径执行。素材生成已在用户批准后完成；保留整图参考、分组提示词与局部细节裁切，记录见 v6 交付文档。

| 素材组 | 需要的内容 | 处理约束 |
| --- | --- | --- |
| 建筑主体 | 商店、旅店、谷仓、四栋住宅、水井 | 独立输出；锁定屋顶比例、门窗和受光；补齐遮挡部分；门口与占地人工校准 |
| 地面材质 | 草地色斑、踩实土路、松土、扁平石板、湿土、河床、水面笔触 | 输出适合平铺/混合的材质，不带整块场景或多余边框；程序负责连接拓扑 |
| 河岸 | 大小岸石、半浸石、苔藓石、草根边、岸花、少量芦苇 | 透明切片，保持自然缺口；水下部分与陆上部分可分层 |
| 路面构件 | 收边石、石径块、台阶、破边和缝草、少量土路碎石 | 尺寸一致、无统一黑描边；道路方向由布局驱动 |
| 院落与广场 | 正侧向篱笆、转角、院门、灯柱、花箱、木桶、花盆、草垛、箱子 | 根据院落模板成组放置；不随机塞进街道和入口 |
| 农作物 | 小株白菜/叶菜、幼苗、成熟麦穗丛及边缘变体 | 同一植株提供少量形态/阶段变化，密集种植但不合成整块农田图片 |
| 木桥 | 桥面、立柱、前后扶手、桥头连接 | 水平/纵向至少两套可用组合；不能直接旋转有明显立面光照的整张桥图 |
| 树群 | 阔叶树大冠、小树、灌木和林缘花草变体 | 叶团尺度、轮廓密度贴近参考；局部阴影与树冠可独立控制 |

先做一小组样品：一段完整河岸、一栋带院落住宅、一段石板路和一个种植床。实际贴入基准场景检查通过后，再生成剩余变体，避免整批素材沿错误尺度继续扩散。模型输出若改变了目标建筑外观，应回到该资产局部修正；不以新生成的整幅参考图替换用户指定的目标。

素材保存：`output/imagegen/world-v6/raw/`、`scripts/worldgen/prompts/world-v6/`、`public/world/v6/`。保留原图、提示词和加工脚本。逐资产做透明边缘检查，不能继续一刀切地套同一 alpha 阈值误删树叶、绳索和麦穗。

## 6. 执行顺序与每阶段交付

| 阶段 | 工作 | 可直接审阅的交付 |
| --- | --- | --- |
| A：建立基准 | 冻结旧版本；制作与参考对应的固定场景、相机标尺、区域和锚点 | 同尺寸结构对照图、锚点偏差表 |
| B：地形样片 | 生成最小样品；重做岸线、水体、土路、石板收边 | 河岸/水面短视频、四区域静态近景；通过后才扩展素材 |
| C：完整参考城镇 | 替换独立建筑及高分辨率图集，制作院落、桥、广场和农场，统一植被与光影 | 1536×1024 实机全景、八个区域的原尺寸裁切 |
| D：程序化推广 | 将已验证的结构变为城镇模板与边界装饰规则，接入新版本生成器 | 多种子城镇、河道弯曲/交汇、跨 chunk 与环面接缝场景 |
| E：三轮验收 | 按下列三轮顺序检查和修正，输出最后一轮实际状态 | 两后端截图、动态图、测试报告、遗留差异记录 |

阶段推进默认连续执行；方案确认后不再为常规读写、调参和生成批次反复请求确认。若确实涉及新的成本约束或环境权限，才说明具体原因。

## 7. 实现后的三轮验收标准

1. **整体核对**：相同画幅、时间与相机；检查河流、桥头、广场、水井、七栋建筑、农场的位置和占比，以及院落退距和留白。先比较轮廓与结构，再看颜色。目标场景中不能用“本次随机没生成”跳过参考图里的主要对象。
2. **细节核对**：逐一对照本方案八个裁切区域，在原尺寸检查石缝、瓦片、门槛、栏杆、草根、浅水石、涟漪、作物密度、根影和田垄。不允许用远景缩图隐藏差异，也不以整体调色替代缺失的物件。
3. **动态与跨场景核对**：水流方向、植物风动、角色前后遮挡、桥上行走、院门进出、暂停冻结；检查多种子、宽窄河道、弯道和世界接缝；WebGPU/WebGL 对照。新效果应在动态游玩时成立。

辅助量化：固定场景的人工标注锚点、物件包围盒、道路/岸线宽度、作物覆盖和留白比例、分区色彩分布。先建立有对应关系的标注再计算误差；不对不同布局直接算 SSIM，也不将任意综合分数称为“还原百分比”。几何误差与性能预算在阶段 A 记录为可重复的基线。

工程检查：保留现有 `npm run verify` 与 `npm run build`；增加岸线装饰与水陆关系、连续道路宽度、院落入口、田床种植范围、图集分档、版本基线及跨接缝测试。性能记录固定设备和画幅的帧时间、绘制批次、图集显存估算；桌面模拟移动视口不代替真实手机测试。

当前 v5 的测试通过只证明现有功能和渲染可运行，**不证明其视觉已接近参考图**。重构完成时会提供原图与实机对照，以及仍有差异的具体区域。
